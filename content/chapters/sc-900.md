# 第三篇　SC-900 必備知識

> ［考綱權重］安全性、合規性與身分概念 10%\~15%；Microsoft Entra 25%\~30%；Microsoft 安全性解決方案 35%\~40%；Microsoft 合規性解決方案 20%\~25%。新版技能清單自 2026 年 7 月 28 日起適用。

## 第 4 章　安全性、合規性與身分概念

### 4.1　安全性三條主線

| 主題       | 核心                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| Security   | 保護身分、裝置、應用程式、網路與資料，降低機密性、完整性與可用性風險。 |
| Compliance | 遵循法律、法規、契約與內部政策，並能提出證據。                         |
| Identity   | 代表人、裝置、應用程式、工作負載或 AI 代理程式的數位主體。             |

### 4.2　Authentication 與 Authorization

| 階段                               | 問題                       | 例子                   |
| ---------------------------------- | -------------------------- | ---------------------- |
| 身分識別（Identification）         | 宣告你是誰。               | 輸入使用者名稱。       |
| 驗證（Authentication）             | 證明你真的是該身分。       | 密碼、passkey、MFA。   |
| 授權（Authorization）              | 決定已驗證主體可以做什麼。 | 角色、權限與範圍。     |
| 稽核／計責（Accounting／Auditing） | 記錄誰在何時做了什麼。     | Audit logs、活動記錄。 |

> ［口訣］先宣告身分，再驗證身分，最後才授權；「登入成功」不代表「有權刪除資源」。

### 4.3　IdP、目錄服務與同盟

| 概念                             | 一句話                                                            |
| -------------------------------- | ----------------------------------------------------------------- |
| Identity Provider（IdP）         | 驗證使用者並發出可供應用程式信任的權杖。                          |
| Directory Service                | 儲存與管理使用者、群組、裝置及其他目錄物件。                      |
| Active Directory Domain Services | 傳統內部部署網域服務，常用 Kerberos、NTLM、LDAP 與 Group Policy。 |
| Federation                       | 在不同信任網域之間建立身分信任，讓一方接受另一方發出的權杖。      |
| Single Sign-On                   | 一次驗證後存取多個已整合應用程式。                                |

> ［易錯］同盟（Federation）是信任與權杖交換，不等於目錄同步；SSO 是使用者體驗，不是單一產品名稱。

### 4.4　加密、雜湊與 GRC

| 概念       | 定義                                           | 考題關鍵字             |
| ---------- | ---------------------------------------------- | ---------------------- |
| Encryption | 使用金鑰把明文轉為密文，可在有適當金鑰時解密。 | 保護靜態與傳輸中資料。 |
| Hashing    | 單向轉換為固定長度摘要，理論上不可逆。         | 完整性檢查、密碼驗證。 |
| Governance | 設定決策、政策、責任與監督機制。               | 誰負責、如何管。       |
| Risk       | 辨識、評估與處理不確定性對目標的影響。         | 可能性×衝擊。          |
| Compliance | 符合外部法規與內部要求，並保留證據。           | 是否遵循、能否證明。   |

## 第 5 章　Microsoft Entra

### 5.1　Microsoft Entra 家族與 Entra ID

Microsoft Entra 是身分與網路存取產品家族；Microsoft Entra ID 是其中的基礎雲端身分與存取管理服務。舊教材可能寫 Azure Active Directory（Azure AD），目前考試應以 Microsoft Entra ID 名稱為準。

| 產品／能力                      | 定位                                                   |
| ------------------------------- | ------------------------------------------------------ |
| Microsoft Entra ID              | 雲端 IAM，提供驗證、授權、原則與身分保護。             |
| Microsoft Entra Domain Services | 受管理的 LDAP、Kerberos、NTLM 與 Group Policy。        |
| Microsoft Entra External ID     | 合作夥伴、來賓與消費者身分存取。                       |
| Microsoft Entra Workload ID     | 保護應用程式、服務、容器與自動化工作負載身分。         |
| Microsoft Entra Agent ID        | 為 AI 代理程式提供可治理、可授權、可稽核的非人類身分。 |
| Microsoft Entra ID Governance   | 管理身分生命週期、權限、存取要求與檢閱。               |
| Microsoft Entra ID Protection   | 偵測、調查與修復身分風險。                             |

> ［2026 新版明列］SC-900 2026 年 7 月 28 日版技能清單明列 Agent ID。記住它的本質：AI 代理程式也需要獨立、最低權限、可追蹤的身分，不能大家共用一把萬能金鑰。

### 5.2　混合式身分與身分類型

| 類型                          | 說明                                                                   |
| ----------------------------- | ---------------------------------------------------------------------- |
| 使用者身分                    | 員工、學生、合作夥伴或消費者。                                         |
| 群組                          | 集合多個主體，方便授權與管理。                                         |
| 裝置身分                      | 代表已註冊、已加入或混合式加入的裝置。                                 |
| 服務主體（Service Principal） | 應用程式在租用戶中的身分執行個體。                                     |
| 受控識別（Managed Identity）  | Azure 資源可用的受管理工作負載身分，免自行保存密碼或憑證。             |
| 工作負載身分                  | 應用程式、服務、容器與自動化流程等非人類身分。                         |
| Agent ID                      | AI 代理程式的可治理身分。                                              |
| 混合式身分                    | 整合內部部署 AD DS 與 Microsoft Entra ID，讓使用者跨環境使用一致身分。 |

### 5.3　驗證方法、MFA 與密碼管理

| 方法／能力                       | 重點                                     |
| -------------------------------- | ---------------------------------------- |
| Password                         | 知識要素；單獨使用風險較高。             |
| Microsoft Authenticator          | 推播、一次性密碼或無密碼驗證。           |
| FIDO2／Passkey                   | 抗網路釣魚的公開金鑰驗證。               |
| Windows Hello for Business       | 與裝置綁定的金鑰式驗證。                 |
| Certificate-based Authentication | 使用憑證驗證。                           |
| Temporary Access Pass            | 限時通行證，可用於註冊無密碼方法與復原。 |
| SSPR                             | 使用者依原則自行重設密碼。               |
| Password Protection              | 封鎖弱密碼與自訂禁用密碼字詞。           |

MFA 必須使用兩個以上不同類型的要素，例如「知道的東西、擁有的東西、你本身的特徵」。兩個不同密碼仍屬同一類要素，不能算真正的 MFA。

### 5.4　Conditional Access

| 構成                             | 內容                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| 訊號（Signals）                  | 使用者／群組／代理程式、IP 位置、裝置狀態、應用程式、即時風險。 |
| 決策（Decisions）                | 封鎖存取或授予存取。                                            |
| 授予控制（Grant controls）       | 要求 MFA、驗證強度、合規裝置、混合式加入裝置、核准用戶端等。    |
| 工作階段控制（Session controls） | 限制、監視或調整工作階段行為。                                  |

> ［核心句型］Conditional Access 是 Zero Trust 原則引擎，常以「若特定使用者從高風險位置存取敏感應用程式，則要求 MFA 或封鎖」呈現。它在第一要素驗證完成後評估。

### 5.5　Entra 角色、Azure RBAC、PIM、Access Reviews 與 ID Protection

| 能力                  | 做什麼                                                                                   | 題幹動詞           |
| --------------------- | ---------------------------------------------------------------------------------------- | ------------------ |
| Microsoft Entra roles | 管理租用戶與目錄能力，例如 Global Administrator、User Administrator。                    | 目錄／租用戶管理。 |
| Azure RBAC            | 管理 Azure 資源，例如訂用帳戶、資源群組、VM。                                            | Azure 資源授權。   |
| PIM                   | 以 JIT、限時、需核准與需 MFA 的方式啟用高權限角色。                                      | 臨時提權。         |
| Access Reviews        | 定期確認群組、應用程式與角色的存取是否仍有必要。                                         | 定期回收過度權限。 |
| ID Protection         | 偵測 risky users、risky sign-ins 與 risk detections，並可結合風險式 Conditional Access。 | 身分風險。         |
| ID Governance         | 涵蓋身分生命週期、權限管理、存取套件、工作流程與檢閱。                                   | 治理總集合。       |

> ［口訣］PIM 是「需要時才提權」；Access Reviews 是「定期確認還需不需要」；ID Protection 是「偵測身分風險並促成修復」。

## 第 6 章　Microsoft 安全性解決方案

### 6.1　Azure 核心基礎設施安全服務

| 服務                            | 主要功能                                                       | 題幹線索                       |
| ------------------------------- | -------------------------------------------------------------- | ------------------------------ |
| Azure DDoS Protection           | 緩解大量分散式阻斷服務攻擊。                                   | 大量流量淹沒公開端點。         |
| Azure Firewall                  | 受管理、具狀態的網路防火牆，支援 L3\~L7 規則與集中控管。       | 跨網路集中流量控管。           |
| Web Application Firewall（WAF） | 保護 Web 應用程式免受常見 HTTP／HTTPS 攻擊。                   | SQL injection、XSS、OWASP。    |
| Network Security Group（NSG）   | 以來源、目的地、連接埠與通訊協定控制子網／網卡流量。           | 分散式 L3／L4 存取規則。       |
| VNet segmentation               | 以 VNet、Subnet 與控制項縮小橫向移動。                         | 網路區隔。                     |
| Azure Bastion                   | 透過 Azure portal 以 TLS 連線至 VM，VM 不必暴露公用 RDP／SSH。 | 安全管理 VM。                  |
| Azure Key Vault                 | 集中保護金鑰、祕密與憑證。                                     | 不要把密碼寫在程式碼或設定檔。 |

### 6.2　Microsoft Defender for Cloud

| 概念                  | 定位                                                                 |
| --------------------- | -------------------------------------------------------------------- |
| CNAPP                 | 雲端原生應用程式保護平台的總體概念，整合 CSPM、DevSecOps 與 CWPP。   |
| CSPM                  | 持續評估設定與安全態勢，提供安全建議、Secure Score、標準與法規檢視。 |
| CWPP                  | 針對 VM、容器、儲存體、資料庫、Serverless 等工作負載提供威脅防護。   |
| Secure Score          | 依安全建議量化態勢改善程度；分數上升不代表絕對安全。                 |
| Recommendations       | 指出不安全設定與改善步驟。                                           |
| Regulatory compliance | 把資源狀態對應至安全標準與控制。                                     |

> ［易錯］CSPM 偏「設定是否安全、態勢是否改善」；CWPP 偏「工作負載正在遭受什麼威脅、如何防護」。兩者都在 Defender for Cloud，但題幹動詞不同。

### 6.3　Microsoft Sentinel

| 功能             | 一句話                                            |
| ---------------- | ------------------------------------------------- |
| SIEM             | 集中收集與分析跨來源安全事件，產生警示與事件。    |
| SOAR             | 協調、自動化與回應安全事件。                      |
| Data connectors  | 連接 Microsoft、Azure、內部部署與第三方資料來源。 |
| Analytics rules  | 根據資料偵測威脅並產生 alerts／incidents。        |
| Incidents        | 把相關警示與實體關聯成可調查事件。                |
| Hunting          | 主動以查詢搜尋尚未觸發警示的可疑活動。            |
| Automation rules | 集中定義事件處理與自動化規則。                    |
| Playbooks        | 以 Azure Logic Apps 建立自動回應流程。            |
| Workbooks        | 視覺化安全資料與趨勢。                            |

Microsoft Sentinel 的流程可記為：連接資料 → 偵測 → 建立事件 → 調查／獵捕 → 自動回應。2026 年官方文件也持續把 Sentinel 整合到 Microsoft Defender portal，考題可能提到這個介面變化，但別被介面轉移分心——SC-900 考的核心始終是 SIEM／SOAR 與偵測回應流程本身，不是入口網站長在哪裡。

### 6.4　Microsoft Defender XDR 與各 Defender 產品

| 產品                              | 保護面                                                     |
| --------------------------------- | ---------------------------------------------------------- |
| Microsoft Defender XDR            | 跨端點、身分、電子郵件與應用程式關聯訊號、事件與自動回應。 |
| Defender for Endpoint             | 端點預防、防護、偵測、調查與回應。                         |
| Defender for Office 365           | 保護電子郵件、連結、附件與協作工具。                       |
| Defender for Identity             | 利用內部部署 Active Directory 訊號偵測身分攻擊與橫向移動。 |
| Defender for Cloud Apps           | 跨 SaaS 應用程式可見性、資料控制與威脅防護。               |
| Defender Vulnerability Management | 持續資產可見性、弱點評估與風險式修復優先順序。             |
| Defender Threat Intelligence      | 提供威脅基礎設施、攻擊者與指標的情報。                     |
| Microsoft Defender portal         | 整合 XDR、Sentinel 與多項安全營運工作流程的入口。          |

> ［最常混淆］Defender for Identity 主要看內部部署 AD DS 訊號；Microsoft Entra ID Protection 主要看雲端身分風險；Defender XDR 把多個產品訊號串成完整攻擊故事；Sentinel 可再收集更廣泛的跨雲與第三方事件。

## 第 7 章　Microsoft 合規性解決方案

### 7.1　Service Trust Portal 與 Microsoft 隱私權原則

Service Trust Portal 提供 Microsoft 雲端服務的稽核報告、合規文件、信任與隱私權相關資料。它回答的是「Microsoft 如何證明其雲端服務控制與承諾」，不是替你的組織自動完成所有法規義務。

| 原則                       | 考試層級解釋                             |
| -------------------------- | ---------------------------------------- |
| Control                    | 讓客戶掌握其資料與隱私設定。             |
| Transparency               | 說明資料如何蒐集與使用。                 |
| Security                   | 以安全控制保護資料。                     |
| Strong legal protections   | 依適用法律處理政府與法律要求。           |
| No content-based targeting | 不以電子郵件、聊天或個人內容做廣告定位。 |
| Benefits to you            | 以資料使用為客戶提供價值與功能。         |

### 7.2　Microsoft Purview 與 Compliance Manager

| 能力                     | 定位                                             |
| ------------------------ | ------------------------------------------------ |
| Microsoft Purview portal | 整合資料治理、資料安全與資料合規解決方案。       |
| Compliance Manager       | 評估合規風險、管理改善動作、指派責任與保存證據。 |
| Compliance Score         | 依已完成的改善動作量化進度，協助排優先順序。     |
| Data Map                 | 掃描並建立資料資產中繼資料地圖。                 |
| Unified Catalog          | 讓使用者探索、理解與治理資料產品與資產。         |

> ［警告］Compliance Score 是風險與改善管理指標，不是法律意見、認證保證或「百分之百合規」證書。

### 7.3　資料分類、敏感度標籤與 DLP

| 能力                        | 主要問題                                                           |
| --------------------------- | ------------------------------------------------------------------ |
| Data classification         | 識別資料類型與敏感程度，例如個人資料、財務資料或機密文件。         |
| Sensitive information types | 以模式、關鍵字、驗證邏輯辨識特定敏感資料。                         |
| Sensitivity labels          | 對檔案、電子郵件、容器等套用分類與保護，例如加密、標記與存取限制。 |
| Sensitivity label policies  | 發布標籤、設定預設標籤、強制標示與使用者體驗。                     |
| Data Loss Prevention（DLP） | 偵測敏感資料外流風險，警告、限制或阻擋不當分享。                   |
| Content Explorer            | 檢視已分類或標示內容所在位置。                                     |
| Activity Explorer           | 檢視使用者對敏感內容執行的活動。                                   |

> ［口訣］Sensitivity label 回答「這是什麼等級，如何保護」；DLP 回答「這份敏感資料能不能以這種方式外流」；Content Explorer 看內容在哪裡；Activity Explorer 看發生了什麼活動。

### 7.4　保留、記錄、eDiscovery、Audit 與 Insider Risk

| 能力                    | 題幹動詞                                                   |
| ----------------------- | ---------------------------------------------------------- |
| Retention policy        | 以位置／工作負載為範圍保留或刪除內容。                     |
| Retention label         | 以項目為單位套用保留與處置設定。                           |
| Records Management      | 把內容宣告為記錄，套用更嚴格的保存、處置與證據控制。       |
| eDiscovery              | 在法律、調查或訴訟情境中識別、保留、蒐集、檢閱與匯出內容。 |
| Audit                   | 搜尋與調查使用者及系統活動記錄。                           |
| Insider Risk Management | 以訊號與政策辨識內部人員可能造成的資料風險，並兼顧隱私。   |

> ［易錯］Retention 是「保留多久、何時刪除」；Records Management 是「作為正式記錄治理」；eDiscovery 是「找出並保全法律相關內容」；Audit 是「查誰做了什麼」；Insider Risk 是「辨識內部行為風險」。

## SC-900 必背 25 句

- 身分已成為主要安全界限，不能只依賴內外網路位置。

- Authentication 證明你是誰；Authorization 決定你能做什麼。

- Federation 是信任與權杖交換，不是目錄同步。

- Zero Trust 三原則是明確驗證、最低權限與假設入侵。

- Encryption 可逆且依賴金鑰；Hashing 是單向摘要。

- GRC 分別回答如何治理、有哪些風險、是否符合要求。

- Microsoft Entra ID 是雲端 IAM；舊稱 Azure AD。

- Agent ID 讓 AI 代理程式具備可治理、可授權、可稽核的身分。

- 受控識別讓 Azure 資源存取服務時不必自行保存祕密。

- MFA 需要不同類型的驗證要素。

- Conditional Access 是「若條件成立，則封鎖或要求控制」。

- Entra roles 管租用戶與目錄；Azure RBAC 管 Azure 資源。

- PIM 提供 JIT、限時與需核准的高權限存取。

- Access Reviews 定期確認存取是否仍有必要。

- ID Protection 偵測 risky users、risky sign-ins 與 risk detections。

- WAF 保護 Web 應用程式；NSG 控制子網／網卡流量；Firewall 做集中網路控管。

- Bastion 讓 VM 不必暴露公用 RDP／SSH。

- Key Vault 用來保護金鑰、祕密與憑證。

- Defender for Cloud 的 CSPM 改善態勢；CWPP 防護工作負載。

- Sentinel 是雲端原生 SIEM／SOAR。

- Sentinel Playbook 建構於 Azure Logic Apps。

- Defender XDR 跨端點、身分、郵件與應用程式關聯攻擊。

- Service Trust Portal 提供 Microsoft 的信任與合規證據。

- Sensitivity label 分類與保護；DLP 防止不當外洩。

- eDiscovery 找證據；Audit 查活動；Retention 管保存；Insider Risk 看內部行為風險。
